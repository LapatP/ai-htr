The shape of it

The five stages

Each stage does one thing and hands a well-defined object to the next. That separation is what lets stage 4 be swapped later without touching anything above it.

STAGE 0

Normalize

Built normalize.py · 125 lines

Whatever came off a phone or a flatbed has to become the same kind of object before anything else can reason about it. Three steps. Deskew runs Canny edge detection then a Hough transform to find straight segments, keeps only those spanning at least 30% of the page width and within 15° of horizontal, and takes their median angle — the forms are covered in long printed rules, which is an unusually strong signal, and handwriting strokes are too short to outvote them. CLAHE evens out lighting so a desk photo and a scan present the same features. Letterbox resizes into canonical space preserving aspect ratio and padding with white, rather than stretching, which would inject distortion the next stage has to undo.

Input

Any JPEG or PNG page, any size, any tilt

Output

NormalizedPage — grayscale 2480×3508, upright, plus the skew angle and scale it removed

Evidence

Found 0.92° on the angled Neuro photo, 0.64° on Nutrition. Round-trip deskew tested at four angles.

STAGE 1

Identify the form

Built formid.py · 131 lines

The keystone. ORB finds up to 5000 keypoints — distinctive corners and rule intersections — and fingerprints each one. Those get matched against every known template, filtered by Lowe's ratio test (if a keypoint's best and second-best matches are equally good it is ambiguous, so it is discarded — critical on forms full of repeated checkboxes and dotted rules), then fed to RANSAC, which finds the largest set of matches that agree on a single transform. The size of that agreeing set is the score. A trained classifier was rejected because it always names one of its classes; this can decline, which matters when the hospital form family runs to dozens of variants we will never all have.

Input

A normalized page, plus the template store

Output

A ranked list, and a form_id only if the winner clears both gates — otherwise UNKNOWN

Gates

≥ 25 inliers, and ≥ 6.5× the runner-up

Evidence

4 / 4 known forms correct. 8 / 8 unseen forms correctly refused.

STAGE 2

Register

Built register.py · 124 lines

Same machinery as stage 1, but now the transform itself is the product. A homography is a 3×3 matrix describing how one flat plane maps onto another under any camera viewpoint — rotation, scale, shift and perspective keystone all in one object. Paper is flat, so it is exactly the right model. Once applied, the page occupies the same coordinate system as its template, which is what makes fixed box coordinates valid again. The result object carries its own diagnostics — inlier count, inlier ratio, mean reprojection error over inliers only — because everything downstream trusts this step and a silent bad fit would poison all of it.

Input

A normalized page and its chosen template

Output

Warped page in canonical space, plus a RegistrationResult that knows whether to believe itself

Evidence

0.35 px mean error clean, 0.30 px degraded, 0 failures in 40 trials — against a BP field roughly 175×73 px

STAGE 3

Crop the fields

Built crop.py · 96 lines

Mechanically the easiest stage — read boxes from the config, slice the warped page, write out crops. The hard part was the human judgement: somebody has to say this rectangle is the BP field. All nine are now drawn. Two boxes get stored per field, mirroring the SiData+ dataset's own layout — a tight one around just the value, and a wider context one that includes the printed BP and mmHg labels. Crops are padded generously, because the scoring metric here is coverage, not IoU. Insert fields are the interesting case: the sticker is located at runtime by registering its template into the page, then its boxes are projected through that homography.

Input

Warped page + the form's field list

Output

One tight and one context crop per field

Evidence

All 8 fields crop correctly, verified on the contact sheet. Insert projection lands the sticker origin on (252, 962) exactly, 99% inliers.

STAGE 4

Read the values

Baseline only digits.py + read.py · 290 lines

The only stage that needs a model, and the only one that will touch the GPU. Three readers are declared in the schema, one per BP encoding pattern. The output contract is deliberate: two integers, never a string. 143/90 misread as 14/390 is a one-character slip and clinical nonsense, so accuracy has to be measured per entity rather than per character. The shipped baseline classifies segmented glyphs against templates rendered from OpenCV's Hershey faces — closed-set, so it cannot invent a digit, but vector fonts do not resemble pen strokes at 103 DPI and it reads poorly. Replacing it needs real handwritten digit data or the Typhoon OCR 1.5 route (2B, Apache 2.0, Thai-tuned; its 4-bit QAT variant fits the 8 GB card).

Input

Tight and context crops from stage 3

Output

{ systolic: int, diastolic: int, confidence: float }

Hard requirement

Calibrated confidence and a human-review threshold, day one — not phase two

Reality check

The baseline reads 143/90 as 111/10. Every error was caught downstream and flagged, so nothing wrong escaped — but the reader itself is not usable yet.

Supporting machinery

Not part of the runtime path, but the project does not work without them. These are what make a new form cost a config file instead of a code change.

schema.py

Built

Declares the seven field archetypes and three BP patterns, loads and validates form YAML, and reports which boxes are still undrawn. A form is data, not code — this file is what enforces that.

synth.py

Built

Manufactures a plausible second scan: a homography we chose, plus blur, sensor noise and JPEG artefacts. With one page per form this is the only way to measure anything honestly.

build_templates.py

Built

Turns raw corpus pages into canonical templates. With one sample per form the sample is the template — a circularity that shapes how everything gets evaluated.

eval_registration.py

Built

Warps a template by a known transform, asks the pipeline to recover it, and reports where a grid of points lands. Ground truth is exact because we chose the transform.

calibrate_margin.py

Built

Measures the confidence threshold instead of guessing it, by comparing margin distributions for forms that have templates against forms that do not.

check_formid.py

Built

Runs identification across all 12 pages and writes red/cyan alignment overlays. Note these are self-matches — a plumbing check, not evidence.

box-tool.html

Built

Self-contained 1.5 MB page — templates embedded as data URIs, so it opens by double-click with no server. Pick a field, drag a rectangle, nudge the edges numerically. Wheel zoom anchors under the cursor, and a 5× loupe follows the pointer for placing small boxes.

apply_boxes.py

Built

Writes the tool's JSON back into the configs, crops the triage sticker template out of the base card, and rebases the sticker's two BP boxes into sticker-relative coordinates so they survive it being glued on crooked.

refine.py

Built

Grow-only, and that word was earned: free refinement measured min coverage 0.230 under moderate degradation against 0.973 with none at all — the feature built to stop clipping was itself clipping on degraded scans. It grows a crop to the ink actually present, and raises possibly_clipped when ink runs to the edge of its context or field_empty when nothing was written. Replayed against the real bug it recovers the clipped digit to within 2 px and converges on the same box whether the starting rectangle was right or wrong.

validate.py

Built

Clinical plausibility guardrail. Grades a reading impossible / implausible / plausible and says why — never rewrites it. The load-bearing rule is that systolic must exceed diastolic, which is definitional, free, and the only thing in the pipeline that catches a clipped leading digit. Also surfaces readings sitting near a decision threshold, where one wrong digit flips management.

Process dropped scans.cmd

Built

The batch entrypoint. Drag scans onto it, or double-click to process the inbox; it opens the report itself. Underneath, python -m aihtr takes a folder and writes a self-contained report.html showing the raw input beside every crop, systolic and diastolic as separate numbers, and flagged rows highlighted, plus a manifest and the crop files, at about 0.4 s a page. Reading is off by default — emitting numbers from a reader this weak would invite someone to believe them.

eval_cropping.py

Built

Pushes each page back through stages 0-3 under four levels of manufactured re-scan damage and scores coverage against the clean run. It is what caught refinement destabilising the crop — a bug invisible in the aggregate, which looked fine at mean 0.954.

make_synthetic.py

Built

Renders plausible BP values into known boxes across all four forms, warps and degrades the page, and writes ground truth beside it — so the cropper can be scored rather than eyeballed. A quarter of values are deliberately written larger than their box; refinement captured every one at 1.000 coverage.

Real-scan eval set

Not started

Hand-labelled boxes on genuine scans. Everything measured so far is synthetic; without this there is no way to know what the domain gap actually costs.

What is being extracted

One clinical concept, five places, three structurally different encodings. Narrow enough to finish; broad enough that surviving it proves the multi-template design works.

Decisions and corrections

What changed, and why. The corrections are the more useful half — each one is a place where a plausible assumption turned out to be wrong under measurement.

The printed run number is not a form ID

Disproved

Every page carries a print code in its footer, which looked like a free machine-readable form identifier. It is not: Nutrition 0190 and the Chest clinic form both carry 3591/30,000/Mat.10039712 despite entirely different layouts. It marks the paper stock and print batch, not the form.

No harm done — stage 1 was already designed around feature matching. But it removed a shortcut, and it is recorded so nobody proposes it again.

The confidence threshold was guessed, then measured

Corrected

Stage 1's margin gate started at 1.5×, which let five wrong forms through. Seven of the twelve pages are the same base OPD card with a different overlay printed on it, so a wrong form still earns real inliers from shared header, rules and footer.

Measuring the actual distributions under perturbation gave correct-form margins of 14.3×–152× against wrong-form margins of 1.0×–3.1×. 6.5 sits in that gap with roughly 2× clearance on both sides, and a test pins it so it cannot quietly drift back down.

Straightening the page could break registration

Corrected

Deskew measures page tilt from the median angle of the printed rules — exact under pure rotation, catastrophic under perspective, where keystone stops the rules being parallel and the median becomes meaningless. It reported −8.5° on a page tilted −2.5°, and normalising then left the page more crooked: registration dropped from 63 inliers to 19 and failed outright.

The lines announce their own unreliability — parallel rules spread 0.06–0.47°, perspective spreads 3.5–7.3° — so above a threshold deskew now declines and leaves the page alone. Safe, because a homography absorbs rotation regardless: 10° registers fine with 2,000+ inliers and no straightening at all.

The card was being dragged around by its sticker

Corrected

Inserts exist because a triage sheet is glued on by hand and lands somewhere different each time. That case had never been tested — every evaluation perturbed the whole page, which moves the sticker with the form. Testing it properly showed the sticker carrying 89–100% of the registration inliers, so the page was being aligned to the sticker rather than the card: moving it 60 px dropped the card's own BP field from 1.000 similarity to 0.018.

Fixed by masking declared insert regions out of the template before both form identification and registration. The same fix cured a second symptom — a card with no sticker at all had been failing identification outright.

A follow-up sweep found the sticker can sit essentially anywhere — shifted 1100 px, rotated 90°, rescaled, even hanging off the page edge — with the card unaffected. The one case that did break was a sticker lying on top of a field, which cropped the sticker's content and raised nothing; fields overlapping an insert's footprint are now flagged occluded_by.

Canonical space is 300 DPI even though every source is 103

Decision

All twelve pages are LINE exports capped at 1200 px tall. Pinning canonical space to that would force every future good scan to be downsampled to match, and that loss would be permanent. Upsampling today is lossy but harmless, and the configs never need rewriting.

Crops are scored on coverage, not IoU

Decision

IoU is the standard box metric and the wrong one here. A crop at 0.6 IoU that clips the 0 off 90 is a total failure; 0.6 IoU with generous margin is fine. The reader downstream does not mind whitespace, so boxes are padded deliberately.

LocateAnything-3B dropped

Decision

Attractive for zero-shot auto-labelling, but ~7 GB in bf16 on an 8 GB card, Linux-only with no WSL installed, and weakest exactly where this task lives — small text on a large document. Its licence also bars commercial use, which would matter for anything that becomes a real hospital tool.

Two environment traps, found the hard way

Fixed

OpenCV 5.0 changed HoughLinesP's output shape from (N,1,4) to (N,4). And Hough reads angles clockwise-positive with y pointing down, while getRotationMatrix2D turns counter-clockwise — so rotate(img, a) shifts measured skew by −a. The pipeline had this right; the first test did not.

Constraints worth remembering

  • Resolution ceiling. Sources are ~103 DPI. Cropping is unaffected; reading is capped, and vital-sign digits are the highest-stakes characters on the page.
  • RTX 5050 is Blackwell (sm_120). PyTorch must come from the CUDA 12.8 index or it installs cleanly and fails at runtime with "no kernel image is available".
  • 8 GB VRAM is the hard ceiling on any model choice. Nothing has touched the GPU yet — the whole pipeline so far is classical CV on CPU, 196 MB of dependencies.
  • Python 3.12, not the py launcher's default of 3.14, where ML wheels are patchy.
  • Everything stays local. The eventual inputs are patient records, and open weights on-prem sidesteps the cross-border transfer problem entirely.
  • The SiData+ dataset is gated and access is still pending. It has 500 synthetic pages of one template — content and noise variety, zero layout variety.
